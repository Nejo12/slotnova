# Phase 0 — Architecture & Engineering Foundation Gate

No product implementation begins until this gate is explicitly approved.

## Required decisions

- [ ] repository/monorepo structure approved
- [ ] modular-monolith boundaries approved
- [ ] frontend stack approved
- [ ] backend/runtime stack approved
- [ ] PostgreSQL/data-access strategy approved
- [ ] tenancy model approved
- [ ] time/timezone model approved
- [ ] money model approved
- [ ] API contract/versioning strategy approved
- [ ] asynchronous jobs/outbox strategy approved
- [ ] authentication/authorization boundary approved
- [ ] audit/security baseline approved
- [ ] testing architecture approved
- [ ] motion/accessibility standard approved
- [ ] observability baseline approved
- [ ] CI quality gates approved
- [ ] Spec Kit initialized and constitution reviewed
- [ ] Superpowers installed/verified for Claude Code
- [ ] Claude Code project instructions verified
- [ ] independent architecture review completed
- [ ] review findings reconciled into ADRs/docs
- [ ] first implementation issue is bounded and dependency-safe

## Gate rule

The founder approves Phase 0 by merging the foundation PR after the checklist is satisfied. A merge is not merely documentation acceptance; it authorizes implementation against the committed architecture.

If a major architectural choice remains disputed, leave it marked Proposed and do not start dependent implementation.
